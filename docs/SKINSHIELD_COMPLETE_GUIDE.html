1. The idea, in plain English

Imagine you notice an unusual patch on your skin. You take a photo with your phone and type a short description: "red itchy patch on my forearm, started three days ago." You upload both.

SkinShield answers with two things, always in this order:

  1. Is it possibly contagious? If yes → "This could be infectious — please see a doctor and avoid close contact."
  2. If it is not contagious, what is it? → names the most likely condition out of hundreds.
Why this order matters. In medicine, the worst mistake a computer can make is to wrongly say "you're fine." So we made the system answer the safety-critical question first (is it contagious?), and only then attempt the harder, finer question (what exactly is it?).

That is the whole product. Everything below is how we built it, and how well it performs.

2. Background concepts (start here if new to AI)

Skip this section if you already know machine learning. If not, read it — the rest of the document will make far more sense.

2.1 What is "machine learning"?

Normally, we program computers by writing exact rules: "if the temperature is above 100, turn on the fan." But nobody can write exact rules for "is this a melanoma?" — even dermatologists rely on experience. Machine learning flips the approach: instead of writing rules, we show the computer thousands of examples with the correct answers, and it figures out the patterns itself.

2.2 What is a "neural network"?

A neural network is a large mathematical function with millions of adjustable numbers (called parameters or weights). You feed it an input (e.g. an image), it produces an output (e.g. a disease name). During training, the computer nudges all those numbers slightly so that the answers get closer and closer to correct. Think of it as tuning millions of dials until the machine behaves.

2.3 What is an "embedding" or "feature vector"?

Computers cannot compare pictures directly. So a model converts an image into a list of numbers — for example, 512 numbers — that summarise its visual content. This list is called an embedding or feature vector. Two similar images produce similar lists. Everything downstream works with these lists, not the raw pixels.

image of skin  →  [0.21, -0.44, 0.07, ... , 0.88]   ← 512 numbers
text "red rash" →  [0.19, -0.40, 0.11, ... , 0.91]   ← 512 numbers

2.4 What is a "vision–language model"? (and CLIP / DermLIP)

A vision–language model is trained on pairs of (image, description). It learns to place an image and its matching description at nearly the same point in that "number space," and mismatched pairs far apart. The famous general-purpose version is called CLIP. DermLIP is the same idea but trained only on skin images and dermatology text — so it understands skin disease specifically.

2.5 What does "frozen encoder + head" mean?

Training a huge model like DermLIP from scratch is extremely expensive. Instead we reuse it exactly as it is (we "freeze" it — we don't change its numbers) and use it purely as a feature extractor: it turns every image and every text into a list of 512 numbers. Then we train a small, simple classifier (called a "head") on top of those numbers. This is fast, cheap, and effective — like using a very good translator and then just learning to sort its output.

2.6 What is an "ablation study"?

An ablation means: remove one ingredient at a time and see how much performance drops. If we want to prove that combining image + text helps, we train three separate systems — image only, text only, and both — and compare. If "both" wins, the combination is doing real work. This comparison is the scientific heart of the project.

3. The problem we chose to solve

We built a two-stage classifier that takes an image + a piece of clinical text:

image + text
     │
     ▼
┌───────────────────────────────┐
│ STAGE 1 — CONTAGION GATE      │   "Is this infectious / could it spread?"
└───────────────┬───────────────┘
        ┌───────┴────────┐
   INFECTIOUS       NON-INFECTIOUS
        │                 │
        ▼                 ▼
  "see a doctor"    ┌──────────────────────────┐
  (13% of cases)    │ STAGE 2 — NAME THE DISEASE│
                    │ 50-class classifier       │
                    └──────────────────────────┘
An important early decision — the "pivot". The project originally planned to use body sensors (heart rate, temperature, etc.). But no public sensor dataset exists for skin disease, so we changed to image + text. A consequence: any dataset that has pictures but no matching text (e.g. HAM10000, ISIC) becomes unusable, because half of our model needs the text. This one decision shaped everything that follows.

Scope: the task began as 12 diseases and grew to cover the entire ontology of 388 conditions.

4.3 The "ontology" — a family tree of diseases

Derm1M does not just label each image with one word. It places every case on a family tree of diseases. For example:

inflammatory → non-infectious → eczema → contact dermatitis → allergic contact dermatitis
inflammatory → infectious     → viral  → molluscum contagiosum
proliferations → malignant     → melanocytic → melanoma

This tree is extremely valuable, because it tells us two things for free:

  • whether a condition is infectious (could it spread?) — the branch after "inflammatory"
  • whether it is cancerous ("malignant") or harmless ("benign")

4.4 How many conditions are contagious?

The ontology contains 388 conditions. We split them by whether they are infectious:

GroupCountMeaning
Infectious (potentially contagious)49warts, impetigo, cellulitis, syphilis, scabies…
Explicitly non-infectious85lupus, vasculitis, acne, morphea…
Neither (cancers, genetic, hair, nail…)254melanoma, BCC, SCC, nevi, alopecia…
339 of the 388 conditions (≈87%) are non-contagious. Only 49 (≈13%) are infectious. This is exactly why the two-stage design is justified: Stage 1 isolates the dangerous 13%; Stage 2 works on the safe 87%.

One honest note: the tree says "infectious," which is slightly broader than "contagious." A few of the 49 can be caught internally without spreading to others. Using "infectious" is the safe choice — it never under-warns.

5. Dataset curation — turning files into a usable dataset

The downloaded files are useless as-is. The label file (a spreadsheet, ".csv") lists image filenames like youtube/abc.jpg, while the archives contain the files under their plain name abc.jpg. We had to link them together.

Our pipeline (5 steps)

1Download — pulled all 34.5 GB from HuggingFace.

2Extract — unzipped all 9 archives. Some filenames were ~235 characters long, dangerously close to Windows' 260-character limit, so we built in protection for that.

3Link — for every row in the spreadsheet, we looked up the matching image on disk and confirmed it exists.

4Label — we read the family tree for each row and recorded: the specific condition, whether it is infectious, whether it is malignant, and its top-level category.

5Verify — we checked that the number of images matched the number of rows. Result:

[manifest] rows: 423016 | images found: 423016      ← 100% match, none missing
[manifest] infectious rows: 27964 | malignant rows: 21413
Deliverable: one master spreadsheet — manifest.csv — listing all 423,016 cases, each with the path to its image and all its labels. This single file becomes "the dataset" for every later step.
A trap we caught. The word "non-infectious" contains the word "infectious" inside it! A naive search would label every harmless condition as infectious — corrupting the entire safety gate. We wrote the test correctly: "is it infectious, AND NOT non-infectious." Finding and fixing this was essential.

Why can't we train on all 388 conditions?

Because of a "long tail": a handful of conditions have many examples, but most have almost none.

Conditions having at least…How many such conditions
500 examples80
300 examples114
100 examples213
fewer than 5 examples17,027

You cannot teach a computer to recognise a disease from 2 or 3 photos. So we train only on the well-populated conditions and handle the rare remainder with a different technique (zero-shot — see §14).

6. Preprocessing — turning images and words into numbers

Neural networks only understand numbers. So before anything else, every input is converted:

An image becomes numbers

  1. Resize to a fixed 224 × 224 pixels (so every image is the same shape).
  2. Convert pixels to numbers on a standard scale.
  3. Feed through DermLIP's image encoder → a list of 512 numbers.

Text becomes numbers

  1. Split the sentence into word-pieces (called tokens).
  2. Feed through DermLIP's text encoder → a list of 512 numbers.

We do this once and save the numbers to disk ("caching"). This is important: it means later experiments take minutes instead of hours, because re-reading 60,000 images through the encoder is the single most expensive step.

In plain terms: we translate every photo and every description into two "summaries of 512 numbers," and from then on we work only with those summaries. It is like converting every book into a single fingerprint — comparisons become trivial, and nothing needs to be read twice.

7. Splitting the data (train / validation / test)

If you showed a student the exam questions and the answers while studying, then gave the same questions on the exam, they'd score 100% — but you'd have learned nothing about their real ability. Machine learning has the same trap. So we split the data into parts:

PartPurposeAnalogy
Training (80%)the model learns from thesethe textbook
Test (20%)used only to measure final performancethe unseen exam

We also use a technique called stratification: we make sure the mix of diseases is the same in both parts, so the test isn't accidentally full of one disease.

8. The model — DermLIP, explained

We did not build a model from scratch. We adopted DermLIP, a publicly released dermatology vision–language model — and, importantly, one whose weights (trained numbers) are openly available.

PropertyValue
NameDermLIP ViT-B-16
Typevision–language model (image + text)
Size~150 million parameters
Output per input512 numbers (an "embedding")
Trained on403,563 dermatology image–text pairs
PublishedarXiv 2503.14911 · Nature Medicine (2025)
Licencefree for non-commercial academic research

Why this model?

It was trained exclusively on skin data, so it already understands dermatology vocabulary and appearance — far better than a general-purpose model. It is also the natural companion to the Derm1M dataset (the same research group produced both), which makes results comparable and defensible.

Our approach: use it frozen, train a small "head"

Because DermLIP is already excellent, we do not modify it. We use it to produce the 512-number summaries, then train a small classifier ("head") on top. As shown in §12, the choice of head turned out to matter enormously — one of our biggest accuracy gains came from simply using a smarter head.

10. Stage 2 — naming the disease (first results)

Question it answers: out of 50 common non-contagious conditions (including skin cancers), which one is it?
Data: 69,879 cases across 50 classes (melanoma, basal cell carcinoma, squamous cell carcinoma, nevus, psoriasis, eczema, lupus, pemphigus, ichthyosis…).

First results

What it usedAccuracyMacro-F1
image only0.44040.4311
text only0.87340.8736
image + text0.85030.8553

"Macro-F1" is a fairness-aware score: it averages performance across all 50 diseases equally, so rare diseases count as much as common ones. Random guessing among 50 would score about 0.02. So image-only at 0.43 is roughly 21× better than chance.

But something was suspicious: the text-only score (0.87) was almost perfect. That is too good to be true — and it was the clue that led to the next section.

11. A problem we found: the captions give away the answer

We inspected the text descriptions and discovered that many of them literally state the diagnosis:

"This image describes melanoma, a type of skin cancer…"
"This is a clinical skin image, diagnosed as tinea ringworm…"
"This image shows Kaposi's sarcoma…"

So the "text-only" model wasn't clever — it was reading the answer off the page. In the real world, a patient types symptoms, never a diagnosis. This is called data leakage, and it makes scores look better than they are.

We measured it

We counted how often a description contains its own disease name:

DiseaseDescriptions naming the diagnosis
melanoma92%
tinea92%
basal cell carcinoma91%
eczema90%
acne83%
Overall53%

The fix — and the surprising result

We erased the diagnosis name from every description and re-ran everything. This gives the honest picture:

ConfigurationAccuracyMacro-F1
image only0.44040.4311
text (with diagnosis — leaky)0.87340.8736
text (diagnosis erased — honest)0.68790.6814
image + text (leaky)0.85030.8553
image + text (honest)0.70950.7045
Two crucial findings.
  1. The leak was worth about 0.19 macro-F1 — we now report the honest number.
  2. The core hypothesis is proven: with the leak removed, combining image + text (0.7045) beats text alone (0.6814) and image alone (0.4311). This is the exact claim the project set out to demonstrate — and it only became believable after we removed the leak.
Reporting this openly demonstrates rigour: we found a flaw that inflated our numbers, and we corrected it.

12. How we increased accuracy — the full journey

Starting from 0.7045, we applied four improvements, one after another, all measured on the same test data so the comparison is fair.

1Use a third input source — clinical metadata

Every case also carries structured facts we had not used: age, sex, body location (face, foot, nail…), and skin appearance concepts (red, patch, nodule, blister…). We added these ~100 extra numbers on top of the image and text. This creates a "tri-modal" model — three sources instead of two.

ConfigurationMacro-F1
metadata only0.2800
image + text (previous best)0.7045
+ metadata (tri-modal)0.7461

→ Adding metadata gave +4.2 points. Metadata alone is weak, but it adds real information when combined — the hallmark of a useful new input.

2Use a smarter classifier "head"

Our first head was simple logistic regression. We replaced it with two stronger methods: a multi-layer perceptron (a small neural network) and gradient-boosted trees (HistGBM).

HeadMacro-F1
logistic regression0.7461
+ MLP (small neural network)0.8083
+ HistGBM (boosted trees)0.8102

→ A smarter head alone gave +6.4 points — for free. The lesson: with a strong frozen model, the head you put on top matters a great deal.

3Teach the model the disease family tree (our key novelty)

Instead of training the model only to name the disease, we trained a neural network with two jobs at once: predict the broad category (e.g. "inflammatory") and the exact disease. Knowing the category helps the model choose the disease, just as knowing "this is a fruit" helps you decide "apple vs orange." This is ontology-guided hierarchical multi-task learning — our main novel contribution.

ConfigurationDisease macro-F1Category accuracy
Hierarchical multi-task network0.83370.8959

→ +8.8 points over the previous best. The model also predicts the broad category correctly 89.6% of the time — strong evidence it has learned genuine dermatology structure.

4Combine several models (ensembling)

Different classifiers make different mistakes. So we averaged the decisions of logistic regression, the MLP, and HistGBM — a technique called soft-voting — as a robustness check.

ModelMacro-F1
k-NN (retrieval-based, k=15)0.7415
Ensemble (LR + MLP + HistGBM)0.8338

→ The ensemble (0.8338) confirmed the hierarchical result (0.8337) — two independent methods reaching the same number is a strong, trustworthy outcome.

A method that did not help (reported honestly). We also tried "test-time augmentation" — feeding each image normally and flipped, then averaging. It gave no improvement (0.7461). Negative results are part of honest research, so we report it rather than hide it.

Where the model is strong and weak (and why that's a good sign)

Easiest diseases (F1 ≈ 0.97–0.99)

Kaposi sarcoma, seborrheic keratoses, skin tags, neurofibromatosis — all with very distinctive appearances.

Hardest diseases (F1 ≈ 0.63–0.76)

Dermatitis, eczema, psoriasis, cutaneous T-cell lymphoma, lupus — conditions that look like each other.

Why this pattern matters. The model finds visually obvious diseases easy and the overlapping inflammatory conditions hard — exactly the same difficulty pattern human dermatologists face. This is strong evidence the model learned real medical structure, not a statistical shortcut.

14. Bonus: zero-shot classification

We also tested DermLIP's zero-shot ability: name the disease with no training at all, purely by comparing the image to text prompts like "This is a skin image of melanoma." We tested it across 150 conditions.

MetricValueMeaning
top-1 accuracy0.2198correct disease ranked #1 for 22% of cases
top-5 accuracy0.4447correct disease in the top 5 for 44%
random chance0.00671 in 150 — so we are ~33× better than chance

It works best on distinctive conditions (pityriasis rosea 0.78, cheilitis 0.68) and struggles with vague, overlapping ones (dermatitis, keratosis — 0.00), which makes sense: "a skin image of dermatitis" is an inherently ambiguous prompt.

Why it's useful: zero-shot provides breadth (any condition, instantly), while the trained Stage 2 gives depth on well-represented conditions. Together they cover the whole ontology.

16. Glossary

Embedding / feature vector

A list of numbers (here, 512) that summarises an image or a piece of text so a computer can compare them mathematically.

Encoder

The part of a model that converts an input into an embedding.

Frozen

Deliberately not changing a pre-trained model's internal numbers, using it purely as a feature extractor.

Head

A small classifier trained on top of a frozen model's embeddings to make the final decision.

Multimodal

Using more than one kind of input (here: image, text, and structured metadata).

Tri-modal

Our three-input version: image + text + clinical metadata.

Epoch

One full pass of the model over the training data during learning.

Macro-F1

A performance score that treats every disease equally, so rare diseases count as much as common ones.

Balanced accuracy

Accuracy that weights the classes equally, guarding against a model that scores well by always guessing the most common answer.

Leakage

When the input secretly contains the answer, making performance look better than it truly is.

Ablation

Removing one component at a time to measure how much each contributes.

Zero-shot

Classifying correctly without any training, using only a text description of each class.

Ensemble

Combining several models' outputs to get a more reliable result than any single model.

Hierarchical (ontology-guided)

Teaching the model the "family tree" of diseases so it predicts both the broad category and the specific disease.

Train / validation / test split

Dividing data into a part to learn from and a part to fairly measure performance on unseen cases.
