1. Problem statement & framing

Goal. Build a dermatology decision-support model that, given a skin photograph plus clinical text (symptoms/description), performs a safety-first two-stage classification:

image + text
     │
     ▼
┌───────────────────────────┐
│ STAGE 1 — CONTAGION GATE  │   "Is this infectious / potentially contagious?"
│  infectious vs not        │
└─────────────┬─────────────┘
      ┌───────┴────────┐
   INFECTIOUS      NON-INFECTIOUS
      │                  │
      ▼                  ▼
 "seek medical      ┌──────────────────────────┐
  attention;        │ STAGE 2 — DISEASE ID     │
  may be            │  multi-class: which      │
  contagious"       │  condition is it?        │
                    └──────────────────────────┘

Why this framing. A wrong output that reassures a user they are "fine" is the most dangerous error in a medical assistant. The two-stage design makes the safety-critical decision first (is it infectious?), and only then attempts fine-grained identification. It also means the infectious classes never need to be "named" to the user — an infectious result simply routes to seek care.

The pivot that defines the project. The original concept used physiological sensor input. No public sensor dataset exists for skin disease, so the project pivoted to image + text. Consequence: any dataset that is image-only with no paired text (HAM10000, ISIC, Fitzpatrick17k) is structurally unusable — it cannot train or evaluate the text tower. This single constraint drove the dataset choice.

Scope evolution. The task began as a locked 12-class set (5 common + 7 rare diseases) and was expanded to the full Derm1M ontology (~390 conditions), with the contagious/non-contagious gate added.

3. Dataset curation pipeline

The raw Derm1M archives are disconnected: the CSVs list filenames with prefixes, while the archives contain bare filenames. Curation links them into a single labelled index.

  1. Download — all 9 archives + 2 CSVs + ontology (34.5 GB) via huggingface_hub.snapshot_download.
  2. Extract — each archive into E:\imgs\<source>\, with long-path protection (some Derm1M filenames exceed 235 characters, near the Windows 260-char limit).
  3. Link — for each CSV row, resolve image path from the filename prefix and verify existence.
  4. Label — derive condition, infectious flag, malignant flag, and top category from the ontology column.
  5. Verify — confirm image counts reconcile with row counts.

A subtle correctness issue we solved

The string "non-infectious" contains the substring "infectious". A naive search marks every non-infectious row as infectious. The correct predicate is: 
infectious = label.contains("infectious") AND NOT label.contains("non-infectious")
applied identically to the gate labels and to the pathogen-subtype extraction. This bug was found and fixed — it would otherwise have corrupted the entire Stage-1 label set and the subtype breakdown.

4. The ontology discovery — labels for free

Derm1M's hierarchical_disease_label is a structured clinical ontology, not a flat label. Example values:

inflammatory, non-infectious, eczema, contact dermatitis, allergic contact dermatitis
inflammatory, infectious, viral, molluscum contagiosum
inflammatory, infectious, fungal, candidiasis, tinea
inflammatory, infectious, parasitic, scabies
proliferations, malignant, melanocytic, melanoma
proliferations, benign, non-melanocytic, seborrheic keratosis

Because of this structure, several label axes are available directly from the data — no manual labelling of 390 conditions:

AxisValuesRows
Infectioninfectious27,964
non-infectious109,824
Pathogen subtypebacterial / fungal / viral / parasitic10,679 / 7,267 / 6,869 / 3,035
Malignancymalignant / benign21,413 / 42,825
Top categoryinflammatory, proliferations, reaction patterns, hereditary, exogenous, nevus, keratosis, nail, hair, vascular …—
Significance. The contagion gate's ground-truth labels are derived directly from the clinical ontology, which makes them principled and auditable — not heuristic. This is the single biggest de-risking fact of the project.
Important distinction we made explicit. The ontology's non-infectious label only covers the inflammatory branch. Cancers (melanoma, BCC, SCC) live under proliferations and are therefore neither infectious nor "non-infectious". So for the disease-identification stage the correct target set is "everything that is not explicitly infectious", which includes cancers — not merely the ontology's non-infectious subset.

LicenceCC BY-NC-ND 4.0 (non-commercial research)

Why this model. It is trained specifically on dermatology image–text pairs, so it already "knows" the vocabulary and morphology of the domain — far stronger than a generic CLIP. It is the natural pairing with the Derm1M dataset (same research group).

An alternative we evaluated and set aside. DermLIP's larger sibling PanDerm uses a forked open_clip configuration (extra keys pretrain_path, hf_model_name, hf_tokenizer_name) and fails with the standard PyPI open_clip_torch. It would require installing the Derm1M fork. We standardised on ViT-B-16, which loads with the standard library, giving a reproducible, dependency-light pipeline.

6. Methodology — frozen encoder + probe ablation

We do not fine-tune the 150M-parameter encoder (expensive, and unnecessary for the research claim). Instead:

  1. Encode every sample once with the frozen DermLIP model → a 512-d image vector and a 512-d text vector.
  2. Fuse the two vectors → a 1024-d multimodal representation.
  3. Train a lightweight classifier head (standardised features + logistic regression / MLP) on each representation.
  4. Ablate: train and test three heads — image-only, text-only, and fused — on an identical train/test split.
Why the ablation is the scientific core. The project's hypothesis is that combining image + text beats either modality alone. The ablation is the direct test of that hypothesis. All three heads see the same data and the same split, so the comparison is controlled.

Evaluation metrics. Because the classes are imbalanced, we report balanced accuracy and macro-F1 (which weight every class equally) alongside raw accuracy, and — for the gate — the confusion matrix and per-pathogen recall, which expose missed infections.

Reproducibility. A fixed random seed (42) is used for splitting throughout.

Interpretation. Zero-shot succeeds on conditions with distinctive visual patterns and unambiguous names (pityriasis rosea, melasma, tinea cruris) and fails on broad or overlapping categories (dermatitis, keratosis, allergic reaction) — the same easy/hard split seen in the trained heads. This is expected: a generic prompt such as "a skin image of dermatitis" is intrinsically ambiguous because many diseases present as dermatitis. Zero-shot is therefore reported as breadth coverage, complementing — not replacing — the trained Stage-2 head.

9. The caption-leakage investigation

Inspecting the data revealed that many clinical captions name the diagnosis outright, e.g.:

"This image describes melanoma, a type of skin cancer …"
"This is a clinical skin image, diagnosed as tinea ringworm …"
"This image shows Kaposi's sarcoma, a skin disease characterised by …"

Training a classifier on such text makes the task trivial — the model reads the answer. In real deployment a user types symptoms, not a diagnosis, so any score built on these captions is inflated.

9.2 De-leak re-evaluation

We stripped each caption's own diagnosis name (and its distinctive disease words) and re-encoded the text. The image features are unchanged; the split is identical; only the text changes. Result:

ConfigurationAccuracyBalanced accMacro-F1
image_only0.44040.46580.4311
text_raw (leaky)0.87340.87850.8736
text_deleaked0.68790.70460.6814
fused_raw (leaky)0.85030.85510.8553
fused_deleaked (honest)0.70950.71150.7045
Two results of the highest importance.
  1. The leak was worth ~0.19 macro-F1. Removing the diagnosis from the captions drops text-only from 0.874 to 0.681. This is now a quantified, honest figure rather than a hidden inflation.
  2. The multimodal hypothesis is confirmed. On the de-leaked, honest setup:
      fused 0.7045 > text 0.6814 > image 0.4311. The fused model beats both single modalities. Note the reversal: with leaky captions the image hurt (0.855 < 0.874); with clean captions it helps (0.705 > 0.681). This is the clean, defensible evidence that combining image and text genuinely improves classification.

This investigation is included deliberately: identifying and correcting a leakage artefact is a mark of methodological rigour, not a weakness.

Why CPU is acceptable here. The architecture extracts features once (the only expensive step) and then trains tiny heads. Measured throughput: ~137,788 images in ≈ 3.5 h and ~60,079 images in ≈ 1.9 h for feature extraction. Once cached, training and evaluation take seconds to minutes.

Engineering problems solved

  • Windows long-path limit — Derm1M filenames up to ~235 chars; extraction routed through a short root with \\?\ path handling.
  • Gated model access — required accepting the DermLIP licence on the HF account and authenticating the download with a read token (env-var based, not hard-coded into the model API).
  • Library API drift — adapted to open_clip not accepting a token= kwarg, and to pandas 3.0 changing groupby.apply to drop the grouping column.
  • Data-integrity gate — a pre-flight check verifies images exist before any training, after an earlier build silently trained on zero-tensors when extraction failed.

11. Limitations & threats to validity

  1. Caption leakage. A majority of captions name the diagnosis; all text-based numbers are reported both raw and de-leaked, and the de-leaked figures are the ones we stand behind.
  2. Long tail. 17,027 conditions have <5 examples and cannot be trained; they are handled by zero-shot, not by a trained head. We do not claim a 390-way trained classifier.
  3. CPU-only training. Sufficient for frozen-encoder + probe; full fine-tuning of the backbone would require a GPU.
  4. Single-source data. All training data is Derm1M; external validation (planned: SCIN) has not yet been performed.
  5. Skin-tone representation. Not yet stratified/audited across Fitzpatrick or Monk scales — planned as a fairness check.
  6. Label granularity. The ontology contains broad categories (e.g. "proliferations", "systemic disease") that are not specific diagnoses; these are retained only where they are well-populated.
  7. No clinical validation. This is a research model; it is not a diagnostic device and has not been evaluated prospectively.

12. Conclusions & next steps

What has been demonstrated

  • A complete, verifiable multimodal dataset was built from Derm1M: 423,016 image–text pairs, all linked and labelled via the clinical ontology.
  • Stage 1 (contagion gate) detects infections with 93.1% sensitivity and ≥91.5% recall across all four pathogen families.
  • Stage 2 (50-class identification) achieves 0.431 image-only macro-F1 — ~21× chance — with errors concentrated exactly where clinicians also struggle.
  • The multimodal hypothesis is confirmed on a leakage-controlled evaluation: fused (0.705) beats both text-only (0.681) and image-only (0.431).
  • A caption-leakage artefact affecting 53% of rows was found, quantified, and corrected — reported transparently.
  • Zero-shot breadth: without any training, DermLIP names the correct condition in the top-1 for 22% and top-5 for 44% of cases across 150 conditions (~33× chance) — demonstrating ontology-wide coverage.
